# Аким на 5 часов — распредели городской бюджет, получи AI-разбор решения

> **Статус:** контракт и план готовы, код в разработке. Этот README будет обновлён командой AI+data к T+4:15 (feature freeze) с реальными командами запуска, проверенными на чистом клоне. До тех пор раздел «Быстрый старт» ниже описывает целевой сценарий, а не гарантированно рабочий.

## Проблема
Городской управленец распределяет ограниченный бюджет между транспортом, экологией, соцсферой, безопасностью и городскими сервисами — и должен быстро видеть, на что реально влияет каждое решение и какими компромиссами оно оборачивается.

## Решение и киллер-фича
Игрок получает единый виртуальный бюджет (100 у.е.) и каталог из 14 мероприятий по 5 районам условного города. Он принимает ровно 5 решений — и **карта города перекрашивается в реальном времени** на каждый выбор: критические показатели района (<40) видно сразу, а итоговый **Astana Quality of Life Score** обновляется на лету, ещё до того как набор из 5 решений станет допустимым. После отправки набора AI объясняет результат — сильные стороны, риски, компромиссы — на основе уже посчитанных цифр (AI ничего не считает и не придумывает сам).

## Сценарий демо (пример из ТЗ)
1. Открыть симулятор — виден бюджет 100/100 и базовый Score города: **52.56** (Нура — аутсайдер: S1=38, S2=35, оба ниже критического порога 40).
2. Выбрать: Школа + детсад → Нура (M7), Поликлиника → Нура (M8), Освещение и камеры → Нура (M10), Единая цифровая платформа обращений (M12, городская), Перевод частного сектора на чистое топливо → Сарыарка (M5).
3. Карта Нуры перекрашивается из красной в жёлтую/зелёную по ходу выбора; бюджет тратится 95 из 100.
4. Отправить набор → Score вырастает до **56.54 (+3.99)**, критических показателей больше нет, сработала синергия M10+M12 (+2 к B1 в Нуре).
5. AI объясняет: закрыли главный провал по соцсфере и безопасности Нуры, но транспорт и экология района остались нетронутыми — и бюджет почти исчерпан.

## Архитектура
```
┌──────────────┐   POST /simulate (0-5 решений, live)   ┌───────────────────┐
│  Next.js Web  │ ───────────────────────────────────▶  │   Go + Gin API     │
│  (apps/web)   │ ◀─────────────────────────────────── │   (apps/api)       │
│  карта + Score│   POST /explain (5 решений, submit)    │                     │
└──────────────┘                                         │ internal/scoring    │  детерминированный движок,
        ▲                                                │  (Go, чистые       │  считает Score по формуле
        │ GET /catalog                                   │   функции)         │  из contracts/scoring.md
        │                                                │                     │
        │                                                │ internal/llm ──────┼──▶ NVIDIA NIM / OpenAI
        │                                                │  (structured out,  │   (или DEMO_MODE: кэш,
        │                                                │   DEMO_MODE)       │    без сети/ключа)
        │                                                └───────────────────┘
        └──────────────── data/*.json (районы, мероприятия, правила) — единый источник данных, embed в Go, читается фронтом только через API
```
LLM никогда не вызывается с фронта и никогда не пересчитывает числа — только объясняет то, что уже посчитал `internal/scoring`.

## Технологии
- **Backend:** Go 1.26, Gin, без базы данных — датасет из `data/*.json` встроен через `go:embed`.
- **Frontend:** Next.js (App Router, TypeScript), shadcn/ui + Tailwind, точечно ObsidianUI для карты/реакции Score.
- **AI:** один OpenAI-совместимый клиент, по умолчанию NVIDIA NIM (бесплатный тир), структурированный вывод (JSON schema / tool calling).
- **Карта:** реальные геограницы 5 районов (Leaflet/MapLibre + GeoJSON), с откатом на стилизованную SVG-схему, если границы не удастся получить чисто.

Полный контракт API и формулы — в [`contracts/`](contracts/), решения и их причины — в [`.ai/DECISIONS.md`](.ai/DECISIONS.md).

## AI / внешние API и как их проверить
- LLM вызывается только из бэкенда (`internal/llm`), только на `POST /explain` и `POST /compare` — никогда на каждый клик.
- **`DEMO_MODE=true`** отключает реальный вызов LLM и всегда отдаёт кэшированный, помечен `"source": "cached"` ответ — судьи могут проверить весь сценарий вообще без ключей.
- Живой ответ помечен `"source": "live"`; в UI это видно как бейдж. Кэш никогда не выдаётся за живой ответ.
- При сбое реального вызова (таймаут, недоступность провайдера, невалидный структурированный ответ после одной попытки повтора) сервис автоматически откатывается на кэш — демо не падает от сети.

## Тесты
- `data/fixtures/golden.json` — таблица эталонных значений Score (посчитаны и перепроверены независимым скриптом `scripts/verify.py`, см. `contracts/scoring.md`), используется как table-driven тест для `internal/scoring`.
- `scripts/verify.py` — независимая эталонная реализация формулы на Python для перепроверки движка Go.
- Backend: happy path `/simulate`, невалидный ввод по каждому коду ошибки, деградация LLM → кэш.
