# DECISIONS

One line per decision: what, why, rejected alternative. Append, don't rewrite history — if a decision changes, add a new row noting what it supersedes.

| # | What | Why | Rejected |
|---|---|---|---|
| 1 | Backend: Go 1.26 + Gin, one binary | Team wants Go; the core work (validation, deterministic score math) is a good fit for a typed, fast service | FastAPI/Python (template default) |
| 2 | Frontend: Next.js App Router + TS, shadcn/ui + Tailwind base, 2–3 ObsidianUI components for the Score reveal/hero | Boring-and-reliable base the FE owner can use correctly on the first try, with a couple of high-impact animated components where they're seen most | pure ObsidianUI everywhere |
| 3 | No database; `data/*.json` embedded via `go:embed`, `contracts/` in JSON | Dataset is small and static for the hackathon's scope; a DB adds ops risk with no judged benefit | SQLite/Postgres |
| 4 | Roles: FE / BE / AI+data, no lead | Team is 3 people who all want to code; template's "lead" duties (README, contract review, demo) are split across whoever's free | dedicated lead role |
| 5 | Merge via PR + one approval from any teammate; `contracts/` changes need approval from the other side of the contract specifically | Keeps `main` reviewed without a bottleneck gatekeeper | single-gatekeeper lead merges |
| 6 | LLM: one OpenAI-compatible client, NVIDIA NIM by default (`integrate.api.nvidia.com`), OpenAI as a drop-in env swap | Free tier judges can get a key for; NIM and OpenAI share the same request/response shape so one client code path covers both | Anthropic; a bespoke NIM-only client |
| 7 | Jev (TypeSafe's System One model) is **not** used | Released 2026-09-15, early access; it returns typed choices/scores with confidence, not natural-language prose — the wrong shape for "explain this result in Russian for a city manager" | using it for the score-explanation step |
| 8 | LLM called only on `/explain` (submit) and `/compare`, never per-pick | Keeps quota/latency/rate-limit risk to one call in the demo path; the live preview is pure Go math anyway, so nothing is lost | a one-line AI comment per pick |
| 9 | Killer feature: live Score + a **real geo map** (Leaflet/MapLibre, OSM-sourced GeoJSON for the 5 districts), recoloring on every pick | Most visually memorable option in ≤60s; a real map reads as more serious than a stylized graphic | crisis-event killer feature (more original, more scope risk); AI-optimizer-vs-you (needs `/optimum` to be rock solid first) |
| 10 | GeoJSON sourcing: FE pulls from OSM in hour 1; if not clean by Checkpoint 2, fall back to a hand-drawn schematic SVG, labeled as schematic | Nura district was only created in 2022 and may not be cleanly mapped in OSM; the fallback guarantees the killer feature ships regardless | hand-drawing boundaries from the start |
| 11 | Live preview: `POST /simulate` accepts 0–5 decisions, single Go engine is the only source of truth, frontend never reimplements the math | Avoids two engines drifting apart; `contracts/scoring.md` + `data/fixtures/golden.json` are the shared contract test | duplicating the formula in TypeScript for instant client-side feedback |
| 12 | MVP extras beyond the 6 must-haves: optimum-% gauge, A/B/C scenario compare (browser-stored, no DB), city crisis event | Covers 3 of the brief's 4 optional items with the smallest additional surface; team leaderboard needs shared persistence we're deliberately not building | AI "recommends a better swap" (folded into what `/optimum` already shows); auto-generated pitch deck; team leaderboard |
| 13 | Deploy target for judges: local only, `docker compose up` / `make dev`, `DEMO_MODE=true` needs zero keys | Directly serves the 25-point "README & reproducibility" criterion; a hosted demo is one more thing that can be down when judges look | Vercel/Render hosted demo |
| 14 | Docs language: README in Russian (for judges), `.ai/` and `contracts/` in English (for the team/agents), UI copy and LLM output in Russian | Judges read the README; the team works faster in English internally | everything in one language |
| 15 | Cut order if behind schedule: crisis event → compare → optimum gauge → map falls back to SVG (never cut) | Protects the must-haves and the killer feature first; the crisis event is the most original but also the riskiest and least load-bearing for judging criteria | cutting compare or the map first |
